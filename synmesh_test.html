Synapse mesh fetch — Stage 1 feasibility test

Given ONE synapse segment ID (from the raw wei_synapses/syn_20241121 segmentation), fetch and decode its mesh directly from the bucket. This does not search for synapses near a cell — you supply the ID yourself, found by clicking a synapse in Neuroglancer with that layer visible and reading its segment ID off the selection panel.

Waiting for a segment ID…
What a success here proves: the synapse layer's mesh format (neuroglancer_multilod_draco, murmurhash3_x86_128 sharding — confirmed by reading mesh/info directly) decodes correctly with the exact same algorithm core/mesh.js already uses for βJump's own cell meshes, just pointed at a different bucket. It does not prove anything about finding synapse IDs near a given cell — that's the much harder Stage 2 (decoding the raw segmentation volume, since this dataset has no CAVE table or annotation list to query instead).

This page must be opened over https:// (or http://localhost) for fetch()'s Range requests to work — opening the raw file from disk (file://) will fail with a CORS/network error unrelated to the mesh logic itself.
